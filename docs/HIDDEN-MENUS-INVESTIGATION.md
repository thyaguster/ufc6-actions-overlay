# Hidden menu and feature inventory

Archive and live-process investigation on 2026-11-14. Initial scans were read-only. A later bounded test temporarily enabled the debug-menu gate in the running game and restored its original bytes afterward; no game files or saved settings were changed. Raw matches are in `.build/menu-gate-inventory.json` and `.build/hidden-menu-native-readonly.json`; scanners are in `.build/menu_gate_inventory.py`, `.build/extract_hidden_menu_sources.py` and `.build/hidden_menu_callbacks_readonly.py`. The temporary gate probe is `.build/debug_menu_gate_probe.py`.

## Confirmed baseline

- `fe_enable_instant_replays` removes the native `instant_replay` pause-menu item when false. The overlay's Experimental switch has already been tested: the game opens Instant Replay and returns to the fight.

The scripts map the supported Fight Now presets Main Card, Main Event, Championship, Backyard and Kumite to the normal Fight Now route. They also name Dodge, TwoDimensionalFighter and DangerZones, but these have empty route names and are not established as playable options. The menu can only show presets returned by the service. The shared pause menu also removes online opponent/report entries in offline games and hides post-fight View Replay when `Pres_ViewReplayAvailable` is zero. `ui_online_enable_rematch` filters an online rematch entry. These are context gates, not yet useful offline features. Trial-store entries are likewise filtered by SKU and trial state.

The debug-menu probe validated its exact native callback, enabled it for a bounded window, then restored the original `31 c0 c3` bytes. The menu did not exit normally, so the game was closed through its normal window-close path and relaunched through PORTHEON in Parsec mode. The new session loaded v0.9.44 with the debug gate Off. No debug-menu entries were selected or tested.

A second bounded test captured the game window directly at `.build/debug-menu-latest.png`: the debug page displayed one selectable white rectangle with no text, despite the normal game's labels rendering correctly and the footer showing `B BACK` and `A SELECT`. The user confirmed that leaving a Home Page submenu and returning was needed before L3 opened this menu, because Home Page caches the gate. The debug navigation file's root `menu` state has no `back` transition; it has an explicit `goto_homepage` transition instead. This explains why the generic `B BACK` footer does not reliably return to Home Page. The captured rectangle's interior is almost entirely white, but that cannot distinguish white-on-white text from missing text. The gate was again restored, and the blank page remained; the game was closed normally and relaunched through PORTHEON. The new engine's callback bytes were verified as `31 c0 c3` (Off). This confirms the page is visually incomplete in this build; the exact cause of the missing labels is not established.

## Debug-menu label investigation

The debug-menu data record at `ufc_installpackage_00/cas_05.cas` offset `0x2c2f7b8c` contains 12 root items with plain-English `label` values. In order: UFC Homepage; Text Message Widget; RimeECS Debug; RESTART BOOTFLOW; Emojis Test; Movie Tests; Ad Tests; Overlay Loader; Art Tuning; UFC5 Tests; New Feature's Tests; TIN Debug Screens. Its submenus contain additional UI, movie, ad, overlay and fighter-display tests. The root-menu file itself warns that more than 12 entries break its display; it currently has exactly 12.

The generic `NewMenu:ParseMenuItems` source record at `cas_05.cas` offset `0x2ac6cd40` calls `self.loc.LocalizeString(v.label, {case="upper"})` for every item. Working generic menu data uses localization keys such as `TXT_CONTINUE`; the debug menu uses literal text. A bounded test replaced only the first debug label, `UFC Homepage`, with the same-length existing key `TXT_CONTINUE`. It rendered **CONTINUE** in black on the white menu box, captured at `.build/debug-menu-loc-test.png`. This rules out a white-on-white text color for that entry and supports a localization-key mismatch. The original 8,362-byte record was restored and hash-verified after the test.

Two same-size patches to the generic menu source record did not make the full list visible: one selected raw labels by debug-menu path, the other selected raw labels whenever the label lacked the `TXT_` prefix. Both were restored from the exact backup after the user reported blank entries. A read-only scan of all local install packages found no second plain-text `NewMenu:new` source record, so why that script-record patch was ineffective remains unverified. The game is currently relaunched with both archive records restored and the debug gate Off.

Next: do not add a general debug-menu switch. The labels can be read from the data record even though this build does not display them. A full in-game fix would need either a verified localization fallback in the code actually loaded at runtime or appropriate localization entries; the tested generic script-record patch did not take effect. Investigate only a specific useful route if one is identified. The import flag only affects the first-time licensed-fighter tile. CAF Leagues prestige still calls `PrestigeFighter` through its adapter, so enabling its UI gate alone does not establish working offline prestige.
